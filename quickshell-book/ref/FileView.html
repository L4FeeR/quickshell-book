Quickshell.Io

FileView

creatable

Simple accessor for small files.

Import
import Quickshell.Io
Inherits
FileView → QtObject
How to get one
You create this type in QML: FileView { … }.
Default property
adapter — children you write inside FileView { } go here

Overview#

Reads, watches and writes a file. Reading is cheap (no process), and with watchChanges you're notified the moment another program edits the file. With an adapter (JsonAdapter) the file's contents become QML properties.

From the upstream documentation#

A reader for small to medium files that don't need seeking/cursor access, suitable for most text files.

Example: Reading a JSON as text

FileView {
  id: jsonFile
  path: Qt.resolvedUrl("./your.json")
  // Forces the file to be loaded by the time we call JSON.parse().
  // see blockLoading's property documentation for details.
  blockLoading: true
}

readonly property var jsonData: JSON.parse(jsonFile.text())

Also see JsonAdapter for an alternative way to handle reading and writing JSON files.

Example: every property, function and signal#

import Quickshell
import Quickshell.Io
import QtQuick

Column {
    FileView {
        id: fv
        path: Quickshell.statePath("demo.txt")    // "" unloads
        preload: true                             // load as soon as path is set (default)
        blockLoading: false                       // true: text() waits for the first load
        blockAllReads: false                      // true: every read waits for loads
        blockWrites: false                        // true: setText() blocks until written
        atomicWrites: true                        // write to temp file then swap (default)
        printErrors: false                        // don't log missing-file errors
        watchChanges: true                        // emit fileChanged on external edits

        onLoaded: console.log("loaded:", text())
        onLoadFailed: err => {
            console.log("load failed:", FileViewError.toString(err))
            if (err === FileViewError.FileNotFound) setText("created at " + new Date())
        }
        onSaved: console.log("saved")
        onSaveFailed: err => console.warn("save failed:", FileViewError.toString(err))
        onFileChanged: reload()                   // re-read after external change
    }

    Text { text: fv.loaded ? fv.text() : "(not loaded)" }    // text() is bindable
    Text { text: "[append]"; TapHandler { onTapped: fv.setText(fv.text() + "\nmore") } }
    // fv.data()        raw bytes (ArrayBuffer)
    // fv.setData(buf)  write raw bytes
    // fv.waitForJob()  block until the current load finishes
}

Properties#

Every property also emits a <name>Changed signal; handle it with on<Name>Changed (e.g. onPathChanged: …).

NameTypeAccessDescription
pathstringread / write

The path to the file that should be read, or an empty string to unload the file.

preloadboolread / write

If the file should be loaded in the background immediately when set. Defaults to true.

This may either increase or decrease the amount of time it takes to load the file depending on how large the file is, how fast its storage is, and how you access its data.

blockLoadingboolread / write

If text() and data() should block all operations until the file is loaded. Defaults to false.

If the file is already loaded, no blocking will occur. If a file was loaded, and path was changed to a new file, no blocking will occur.

Blocking operations should be used carefully to avoid stutters and other performance

degradations. Blocking means that your interface WILL NOT FUNCTION during the call.

We recommend you use a blocking load ONLY for files loaded before the windows of your shell are loaded, which happens after Component.onCompleted runs for the root component of your shell.

The most reasonable use case would be to load things like configuration files that the program must have available.

Useful for config files read at startup, so nothing flashes with default values. Don't use it for big files.

blockAllReadsboolread / write

If text() and data() should block all operations while a file loads. Defaults to false.

This is nearly identical to blockLoading, but will additionally block when a file is loaded and path changes.

Watch out

We cannot think of a valid use case for this. You almost definitely want blockLoading.

blockWritesboolread / write

If true (default false), all calls to setText() or setData() will block the UI thread until the write succeeds or fails.

Blocking operations should be used carefully to avoid stutters and other performance

degradations. Blocking means that your interface WILL NOT FUNCTION during the call.

atomicWritesboolread / write

If true (default), all calls to setText() or setData() will be performed atomically, meaning if the write fails for any reason, the file will not be modified.

This works by creating another file with the desired content, and renaming

it over the existing file if successful.

printErrorsboolread / write

If true (default), read or write errors will be printed to the quickshell logs. If false, all known errors will not be printed.

watchChangesboolread / write

If true (defaule false), fileChanged() will be called whenever the content of the file changes on disk, including when setText() or setData() are used.

You can reload the file's content whenever it changes on disk like so:
FileView {
  // ...
  watchChanges: true
  onFileChanged: this.reload()
}

Uses inotify. Some /proc and /sys files never notify; for those call reload() on a Timer.

adapterFileViewAdapterread / write

In addition to directly reading/writing the file as text, adapters can be used to expose a file's content in new ways.

An adapter will automatically be given the loaded file's content. Its state may be saved with writeAdapter().

Currently the only adapter is JsonAdapter.

loadedboolread-only

If a file is currently loaded, which may or may not be the one currently specified by path.

Note

If a file is loaded, path is changed, and a new file is loaded, this property will stay true the whole time. If path is set to an empty string to unload the file it will become false.

Functions#

text(): string

Returns the data of the file specified by path as text.

If blockAllReads is true, all changes to path will cause the program to block when this function is called.

If blockLoading is true, reading this property before the file has been loaded will block, but changing path or calling reload() will return the old data until the load completes.

If neither is true, an empty string will be returned if no file is loaded, otherwise it will behave as in the case above.

Note

Due to technical limitations, text() could not be a property, however you can treat it like a property, it will trigger property updates as a property would, and the signal textChanged() is present.

Although it's a function, you can use it in bindings like a property: they update after each load.

data(): string

Returns the data of the file specified by path as an ArrayBuffer.

If blockAllReads is true, all changes to path will cause the program to block when this function is called.

If blockLoading is true, reading this property before the file has been loaded will block, but changing path or calling reload() will return the old data until the load completes.

If neither is true, an empty buffer will be returned if no file is loaded, otherwise it will behave as in the case above.

Note

Due to technical limitations, data() could not be a property, however you can treat it like a property, it will trigger property updates as a property would, and the signal dataChanged() is present.

waitForJob(): bool

Block all operations until the currently running load completes.

Watch out

See blockLoading for an explanation and warning about blocking.

reload(): void

Unload the loaded file and reload it, usually in response to changes.

This will not block if blockLoading is set, only if blockAllReads is true. It acts the same as changing path to a new file, except loading the same file.

writeAdapter(): void

Write the content of the current adapter to the selected file.

setData(data: string): void

Sets the content of the file specified by path as an [ArrayBuffer].

atomicWrites and blockWrites affect the behavior of this function.

saved(s) or saveFailed(s) will be emitted on completion.

setText(text: string): void

Sets the content of the file specified by path as text.

atomicWrites and blockWrites affect the behavior of this function.

saved(s) or saveFailed(s) will be emitted on completion.

Signals#

loaded()handler: onLoaded

Emitted if the file was loaded successfully.

loadFailed(error: FileViewError)handler: onLoadFailed

Emitted if the file failed to load.

saved()handler: onSaved

Emitted if the file was saved successfully.

saveFailed(error: FileViewError)handler: onSaveFailed

Emitted if the file failed to save.

fileChanged()handler: onFileChanged

Emitted if the file changes on disk and watchChanges is true.

adapterUpdated()handler: onAdapterUpdated

Emitted when the active adapter's data is changed.
