Quickshell.Io

Process

creatable

Child process.

Import
import Quickshell.Io
Inherits
Process
How to get one
You create this type in QML: Process { … }.

Overview#

Runs an external program asynchronously and gives you its output. It's the way to use any command-line tool from your shell: brightnessctl, nmcli, curl, your own scripts.

From the upstream documentation#

Example

Process {
  running: true
  command: [ "some-command", "arg" ]
  stdout: @@StdioCollector {
    onStreamFinished: console.log(`line read: ${this.text}`)
  }
}

Example: every property, function and signal#

import Quickshell
import Quickshell.Io
import QtQuick

Scope {
    id: root
    property string out: ""

    Process {
        id: proc
        command: ["sh", "-c", "echo hello $NAME; echo oops >&2; read line; echo got $line"]
        workingDirectory: Quickshell.env("HOME")           // cwd
        environment: ({ NAME: "rice", LANG: "C" })          // extra vars (null value = unset)
        clearEnvironment: false                             // true = start from an empty env
        stdinEnabled: true                                  // allow write()
        running: false                                      // true starts it

        stdout: SplitParser { onRead: line => console.log("stdout:", line) }
        stderr: StdioCollector { onStreamFinished: console.warn("stderr:", text) }

        onStarted: { console.log("pid", processId); write("from-qml\n") }
        onExited: (code, status) => console.log("exit code", code, "status", status)
    }

    Timer {
        interval: 1000; running: true
        onTriggered: proc.running = true                    // start
    }
    // other functions:
    //   proc.signal(15)                 send SIGTERM (or any signal number)
    //   proc.startDetached()            run a copy that outlives Quickshell
    //   proc.exec(["ls", "-la"])        stop current run and start this command now
    //   proc.running = false            kill it
}

Properties#

Every property also emits a <name>Changed signal; handle it with on<Name>Changed (e.g. onRunningChanged: …).

NameTypeAccessDescription
runningboolread / write

If the process is currently running. Defaults to false.

Setting this property to true will start the process if command has at least one element. Setting it to false will send SIGTERM. To immediately kill the process, use signal() with SIGKILL. The process will be killed when quickshell dies.

If you want to run the process in a loop, use the onRunningChanged signal handler to restart the process.

Process {
  running: true
  onRunningChanged: if (!running) running = true
}
See startDetached() to prevent the process from being killed by Quickshell

if Quickshell is killed or the configuration is reloaded.

Becomes false when the program exits. To run the same command again, set it to true again (for example from a Timer).

processIdvarread-only

The process ID of the running process or null if running is false.

commandlist<string>read / write

The command to execute. Each argument is its own string, which means you don't have to deal with quoting anything.

If the process is already running changing this property will affect the next started process. If the property has been changed after starting a process it will return the new value, not the one for the currently running process.

This does not run command in a shell. All arguments to the command

must be in separate values in the list, e.g. ["echo", "hello"] and not ["echo hello"].

Additionally, shell scripts must be run by your shell, e.g. ["sh", "script.sh"] instead of ["script.sh"] unless the script has a shebang.

You can use ["sh", "-c", <your command>] to execute your command with

the system shell.

A list: program first, then each argument. It isn't run through a shell, so no quoting is needed, but pipes and $VARS need ["sh", "-c", "…"].

workingDirectorystringread / write

The working directory of the process. Defaults to quickshell's working directory.

If the process is already running changing this property will affect the next started process. If the property has been changed after starting a process it will return the new value, not the one for the currently running process.

environmentQVariantHashread / write

Environment of the executed process.

This is a javascript object (json). Environment variables can be added by setting them to a string and removed by setting them to null (except when clearEnvironment is true, in which case this behavior is inverted, see clearEnvironment for details).

environment: ({
  ADDED: "value",
  REMOVED: null,
  "i'm different": "value",
})
Note

You need to wrap the returned object in () otherwise it won't parse due to javascript ambiguity.

If the process is already running changing this property will affect the next started process. If the property has been changed after starting a process it will return the new value, not the one for the currently running process.

clearEnvironmentboolread / write

If the process's environment should be cleared prior to applying environment. Defaults to false.

If true, all environment variables will be removed before the environment object is applied, meaning the variables listed will be the only ones visible to the process. This changes the behavior of null to pass in the system value of the variable if present instead of removing it.

clearEnvironment: true
environment: ({
  ADDED: "value",
  PASSED_FROM_SYSTEM: null,
})

If the process is already running changing this property will affect the next started process. If the property has been changed after starting a process it will return the new value, not the one for the currently running process.

stdoutDataStreamParserread / write

The parser for stdout. If the parser is null the process's stdout channel will be closed and no further data will be read, even if a new parser is attached.

stderrDataStreamParserread / write

The parser for stderr. If the parser is null the process's stdout channel will be closed and no further data will be read, even if a new parser is attached.

stdinEnabledboolread / write

If stdin is enabled. Defaults to false. If this property is false the process's stdin channel will be closed and write() will do nothing, even if set back to true.

Functions#

exec(context: ProcessContext): void

Launch a process with the given arguments, stopping any currently running process.

The context parameter can either be a list of command arguments or a JS object with the following fields: - command: A list containing the command and all its arguments. See Process.command. - environment: Changes to make to the process environment. See Process.environment. - clearEnvironment: Removes all variables from the environment if true. - workingDirectory: The working directory the command should run in.

Passed parameters will change the values currently set in the process.

This does not run command in a shell. All arguments to the command

must be in separate values in the list, e.g. ["echo", "hello"] and not ["echo hello"].

Additionally, shell scripts must be run by your shell, e.g. ["sh", "script.sh"] instead of ["script.sh"] unless the script has a shebang.

You can use ["sh", "-c", <your command>] to execute your command with

the system shell.

Calling this function is equivalent to running:

process.running = false;
process.command = ...
process.environment = ...
process.clearEnvironment = ...
process.workingDirectory = ...
process.running = true;

Accepts a command list (or a context object with command, environment, workingDirectory…). Stops any current run first.

signal(signal: int): void

Sends a signal to the process if running is true, otherwise does nothing.

write(data: string): void

Writes to the process's stdin. Does nothing if running is false.

startDetached(): void

Launches an instance of the process detached from Quickshell.

The subprocess will not be tracked, running will be false, and the subprocess will not be killed by Quickshell.

This function is equivalent to Quickshell.execDetached().

Notes, tips and gotchas#

  • Wrap output in .trim().
  • Set environment: ({ LC_ALL: "C" }) when parsing output, so other languages don't change it.
  • For files in /proc or /sys, use FileView instead; it's much cheaper.
