Part T · Theming

th7Theming 7: Theming Your Whole Desktop

A themed bar next to a terminal in different colours looks unfinished. This chapter carries the shell's theme to the rest of the desktop: kitty, Hyprland's window borders and GTK apps follow every theme switch automatically. Then it adds a "From wallpaper" theme generated by matugen to the same library, and covers apps that have their own official themes.

services/ThemeExport.qml
extras/  kitty.conf  gtk.css  hyprland.conf  matugen-config.toml  wallpaper-theme.json.template

How exporting works#

Most programs can't ask the shell for colours, but almost all of them can include a colour file. So the exporter writes small files in each program's own format whenever you choose a theme, and tells the program to reload them:

Program File the shell writes How it reloads
kitty ~/.config/kitty/theming-colors.conf pkill -USR1 kitty (kitty reloads its config on that signal)
Hyprland ~/.config/hypr/theming-colors.conf ($theme_primary and friends) border colours are also set live with hyprctl keyword
GTK 3/4 and libadwaita apps ~/.config/gtk-{3,4}.0/theming-colors.css new windows pick it up; color-scheme is set to light or dark

You add one line to each program's config, once:

theming/extras/kitty.conf# add to ~/.config/kitty/kitty.conf
include theming-colors.conf
theming/extras/gtk.css/* add to ~/.config/gtk-3.0/gtk.css and ~/.config/gtk-4.0/gtk.css */
@import url("theming-colors.css");

And in Hyprland, the source line in extras/hyprland.conf (Theming 5: The Theme Switcher) makes $theme_primary, $theme_border etc. available, so you can use the theme's colours anywhere in your Hyprland config: col.shadow = $theme_background, for example.

The exporter, line by line#

theming/services/ThemeExport.qmlpragma Singleton
import Quickshell
import QtQuick
import qs.services

// Carries the shell's theme to other programs. Whenever the chosen theme changes (not while
// previewing), it writes small colour files that kitty, Hyprland and GTK can include.
// Turn each target on or off with the properties below.
Singleton {
    id: root

    property bool kitty: true          // ~/.config/kitty/theming-colors.conf
    property bool hyprland: true       // ~/.config/hypr/theming-colors.conf + live border colours
    property bool gtk: true            // ~/.config/gtk-3.0/theming-colors.css and gtk-4.0

    readonly property string home: Quickshell.env("HOME")

    // "#cba6f7" (or "#ffcba6f7" with opacity) -> "cba6f7"
    function hex(v: var): string {
        const s = String(v);
        return s.length === 9 ? s.slice(3) : s.slice(1, 7);
    }

    // 16 terminal colours: the theme file's "terminal" list if it has one, otherwise built from roles
    function terminalColors(t: var, c: var): list<string> {
        if (Array.isArray(t.terminal) && t.terminal.length === 16) return t.terminal;
        const base = [c.surfaceHigh, c.red, c.green, c.yellow, c.blue, c.magenta, c.cyan, c.textMuted];
        const bright = [c.textFaint, c.red, c.green, c.yellow, c.blue, c.magenta, c.cyan, c.text];
        return [...base, ...bright].map(x => "#" + hex(x));
    }

    function writeFile(path: string, text: string): void {
        Quickshell.execDetached(["sh", "-c", 'mkdir -p "$(dirname "$1")" && printf "%s" "$2" > "$1"', "sh", path, text]);
    }

    function exportAll(): void {
        // the CHOSEN theme, never a preview: resolve every role of it into c.<role>
        const t = Theme.themes[Theme.chosenId];
        const c = {};
        for (const r of Object.keys(t.roles)) c[r] = Theme.resolve(t, r);
        const name = t.name;

        if (kitty) {
            const term = terminalColors(t, c);
            const lines = [`# ${name}, written by the Quickshell theme switcher`,
                           `foreground #${hex(c.text)}`, `background #${hex(c.background)}`,
                           `selection_foreground #${hex(c.background)}`, `selection_background #${hex(c.primary)}`,
                           `cursor #${hex(c.primary)}`, `url_color #${hex(c.blue)}`,
                           `active_border_color #${hex(c.primary)}`, `inactive_border_color #${hex(c.border)}`];
            term.forEach((col, i) => lines.push(`color${i} ${col}`));
            writeFile(`${home}/.config/kitty/theming-colors.conf`, lines.join("\n") + "\n");
            // kitty re-reads its config (and the include) on SIGUSR1
            Quickshell.execDetached(["pkill", "-USR1", "-x", "kitty"]);
        }

        if (hyprland) {
            const vars = ["background", "surface", "border", "text", "primary", "secondary", "red", "green", "yellow", "blue"]
                .map(r => `$theme_${r} = rgb(${hex(c[r])})`);
            writeFile(`${home}/.config/hypr/theming-colors.conf`, `# ${name}\n` + vars.join("\n") + "\n");
            // apply the border colours right away, without reloading Hyprland
            Quickshell.execDetached(["hyprctl", "--batch",
                `keyword general:col.active_border rgb(${hex(c.primary)}) rgb(${hex(c.secondary)}) 45deg ; keyword general:col.inactive_border rgb(${hex(c.border)})`]);
        }

        if (gtk) {
            const css = [`/* ${name} */`,
                         `@define-color accent_color #${hex(c.primary)};`, `@define-color accent_bg_color #${hex(c.primary)};`,
                         `@define-color accent_fg_color #${hex(c.onPrimary)};`,
                         `@define-color window_bg_color #${hex(c.background)};`, `@define-color window_fg_color #${hex(c.text)};`,
                         `@define-color view_bg_color #${hex(c.surface)};`, `@define-color view_fg_color #${hex(c.text)};`,
                         `@define-color headerbar_bg_color #${hex(c.surface)};`, `@define-color headerbar_fg_color #${hex(c.text)};`,
                         `@define-color card_bg_color #${hex(c.surfaceHigh)};`, `@define-color card_fg_color #${hex(c.text)};`,
                         `@define-color popover_bg_color #${hex(c.surfaceHigh)};`, `@define-color popover_fg_color #${hex(c.text)};`,
                         `@define-color destructive_color #${hex(c.red)};`, `@define-color success_color #${hex(c.green)};`,
                         `@define-color warning_color #${hex(c.yellow)};`, `@define-color error_color #${hex(c.red)};`].join("\n") + "\n";
            writeFile(`${home}/.config/gtk-3.0/theming-colors.css`, css);
            writeFile(`${home}/.config/gtk-4.0/theming-colors.css`, css);
            Quickshell.execDetached(["gsettings", "set", "org.gnome.desktop.interface", "color-scheme", t.variant === "light" ? "prefer-light" : "prefer-dark"]);
        }
    }

    // Export when the chosen theme changes, after a short pause (fast cycling exports once).
    Connections {
        target: Theme
        function onChosenIdChanged(): void { debounce.restart() }
        function onThemesChanged(): void { debounce.restart() }
    }
    Timer {
        id: debounce
        interval: 400
        onTriggered: if (Theme.themes[Theme.chosenId]) root.exportAll()
    }
}

Colour files want cba6f7 or #cba6f7. This accepts a colour or a string, and drops the # (and an opacity prefix if there is one).

lines 24–30Terminal colours
// 16 terminal colours: the theme file's "terminal" list if it has one, otherwise built from roles
function terminalColors(t: var, c: var): list<string> {
    if (Array.isArray(t.terminal) && t.terminal.length === 16) return t.terminal;
    const base = [c.surfaceHigh, c.red, c.green, c.yellow, c.blue, c.magenta, c.cyan, c.textMuted];

    return [...base, ...bright].map(x => "#" + hex(x));
}

Terminals need 16 colours: 8 normal and 8 bright. If the theme file has an exact terminal list, it's used as is. Otherwise they're built from roles: black is the raised surface (dark enough to be "black" on a dark theme), then red, green, yellow, blue, magenta, cyan, and white is the muted text; the bright row uses the faint text as bright black and the main text as bright white.

Lua Hyprland configs

hyprctl keyword works with classic configs. With a Lua config, change the two border calls to hyprctl eval with Lua (hl.config({ general = { col = { active_border = … } } }), check your Hyprland version's wiki), or turn hyprland off and set borders from the generated file.

Apps with official themes#

Many popular themes have official ports for editors and browsers that look better than anything generated: Catppuccin and Tokyo Night have ports for Neovim, VS Code, Firefox, Discord, Spotify, btop and hundreds more. Rather than generating colours for those apps, let the shell tell them which port to use:

// in ThemeExport.exportAll(): switch Neovim's colourscheme to the matching official port
const nvimScheme = ({ "catppuccin-mocha": "catppuccin-mocha", "catppuccin-latte": "catppuccin-latte",
                      "tokyo-night": "tokyonight-night", "tokyo-night-storm": "tokyonight-storm",
                      "tokyo-night-moon": "tokyonight-moon", "tokyo-night-day": "tokyonight-day",
                      "gruvbox-dark": "gruvbox", "nord": "nord", "rose-pine": "rose-pine" })[Theme.chosenId];
if (nvimScheme)
    writeFile(`${home}/.config/nvim/lua/theme.lua`, `vim.cmd.colorscheme("${nvimScheme}")\n`);

Your Neovim config then does require("theme") (after installing those colourscheme plugins). The same idea works for VS Code ("workbench.colorTheme" in its settings.json), btop (color_theme) and any app with named themes.

A "From wallpaper" theme#

Fixed themes and wallpaper-generated colours (Colors and Wallpaper Theming) can live side by side. matugen generates a Material palette from your wallpaper; with the template below, it writes that palette as a theme file into your themes folder, and a post-hook tells the shell to reload:

theming/extras/wallpaper-theme.json.template{
  "id": "wallpaper",
  "name": "From wallpaper",
  "family": "Wallpaper",
  "variant": "dark",
  "author": "matugen",
  "palette": {
    "background": "{{colors.surface.default.hex}}",
    "surface": "{{colors.surface_container_low.default.hex}}",
    "surfaceHigh": "{{colors.surface_container_high.default.hex}}",
    "outline": "{{colors.outline_variant.default.hex}}",
    "text": "{{colors.on_surface.default.hex}}",
    "textMuted": "{{colors.on_surface_variant.default.hex}}",
    "textFaint": "{{colors.outline.default.hex}}",
    "primary": "{{colors.primary.default.hex}}",
    "onPrimary": "{{colors.on_primary.default.hex}}",
    "secondary": "{{colors.secondary.default.hex}}",
    "tertiary": "{{colors.tertiary.default.hex}}",
    "error": "{{colors.error.default.hex}}"
  },
  "roles": {
    "background": "background", "surface": "surface", "surfaceHigh": "surfaceHigh", "border": "outline",
    "text": "text", "textMuted": "textMuted", "textFaint": "textFaint",
    "primary": "primary", "onPrimary": "onPrimary", "secondary": "secondary",
    "red": "error", "orange": "tertiary", "yellow": "tertiary", "green": "secondary",
    "cyan": "secondary", "blue": "primary", "magenta": "tertiary"
  }
}
theming/extras/matugen-config.toml# ~/.config/matugen/config.toml: a "From wallpaper" theme for the switcher
[templates.theming]
input_path = '~/.config/quickshell/theming/extras/wallpaper-theme.json.template'
output_path = '~/.config/theming/themes/wallpaper.json'
post_hook = 'qs -c theming ipc call theme reload'

Now every time you run matugen image ~/Pictures/wall.jpg, a theme called From wallpaper appears (or updates) in the picker, next to Catppuccin and the rest. Select it and the shell, kitty, Hyprland and GTK all take the wallpaper's colours. Select Nord and they all go back.

The template maps Material roles to ours: Material's surface family becomes background/surface/surfaceHigh, primary/on_primary stay primary/onPrimary, and since Material has no full rainbow, the seven accents reuse primary, secondary, tertiary and error.

The complete picture#

One choice in the picker now themes the shell, the terminal, window borders, GTK apps and the editor.

Practice#

Exercise 1Warm-upHook up kitty

Add include theming-colors.conf to your kitty config, open a terminal, and press Super+Shift+T a few times. The terminal should follow.

Exercise 2PracticeFuzzel or rofi

Add an export target for your launcher's config (fuzzel uses [colors] with background=rrggbbaa, rofi uses a .rasi file with @define-style variables). Reload it after writing.

Exercise 3PracticeHyprland shadows

Use the generated variables in your Hyprland config for shadows and group borders: decoration { shadow { color = $theme_background } }.

Exercise 4ChallengeFirefox

Firefox can be themed from a userChrome.css using CSS variables. Export a theming-colors.css for Firefox with --theme-bg, --theme-fg and --theme-accent, import it from userChrome.css, and use the variables for the tab bar.

Exercise 5Mini projectA fully themed desktop

Make one theme switch recolour at least five things: the shell, terminal, window borders, GTK apps and one more app of your choice. Record a short screen capture cycling through Catppuccin Mocha, Tokyo Night and Gruvbox Light.
