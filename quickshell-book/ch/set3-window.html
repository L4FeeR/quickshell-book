set3Settings App 3: The Window, Navigation and Search

The pages need a home: a resizable window with a title, a search field, a navigation rail with one entry per page, and the current page on the right. This chapter builds that window, the small state singleton that drives it, and both ways of opening it.

settings.qml

Module 1: Shared state#

cae/modules/settings/SettingsState.qmlpragma Singleton
import Quickshell
import QtQuick

// What the settings window is showing: the current page and the search text.
Singleton {
    property int page: 0
    property string query: ""

    // page id, label, icon. The order here is the order in the navigation rail.
    readonly property var pages: [
        { id: "appearance", label: "Appearance", icon: "palette" },
        { id: "frame", label: "Frame", icon: "crop_free" },
        { id: "bar", label: "Bar", icon: "view_sidebar" },
        { id: "panels", label: "Panels", icon: "dashboard" },
        { id: "services", label: "Services", icon: "tune" },
        { id: "keybinds", label: "Keybinds", icon: "keyboard" },
        { id: "profiles", label: "Profiles & data", icon: "inventory_2" }
    ]

    // case-insensitive match of the search text against any of the given strings
    function matches(a, b, c): bool {   // untyped: missing arguments stay undefined
        const q = query.trim().toLowerCase();
        return !q || [a, b, c].some(t => (t ?? "").toLowerCase().includes(q));
    }
}

lines 22–25One matching rule
function matches(a, b, c): bool {   // untyped: missing arguments stay undefined
    const q = query.trim().toLowerCase();
    return !q || [a, b, c].some(t => (t ?? "").toLowerCase().includes(q));
}

Every row asks this function whether it matches: the search text is lower-cased and looked up in up to three strings. The function is deliberately untyped. With (a: string, …), a missing argument would be converted to the string "undefined", and a search for "def" would match rows that never mention it.

// The page list on the left. While searching, each page shows how many settings match.
ColumnLayout {
    id: root

    required property var counts       // matches per page while searching

    Repeater {

            id: item

                    text: item.modelData.icon

                    color: item.active ? Colours.palette.m3onSecondaryContainer : Colours.palette.m3onSurfaceVariant
                }
                StyledText {
                    Layout.fillWidth: true
                    text: item.modelData.label
                    font.weight: item.active ? 600 : 400
                    color: item.active ? Colours.palette.m3onSecondaryContainer : Colours.palette.m3onSurface

                StyledRect {
                    visible: SettingsState.query !== "" && item.count > 0
                    implicitWidth: Math.max(22, badge.implicitWidth + 10)
                    implicitHeight: 22

            }
            StateLayer {
                radius: Tokens.rounding.full

            }
        }

Each entry is a pill: filled with the secondary container colour and a filled icon when selected. While searching, pages with matches show a badge with the count and pages without matches fade to 40%, so you can see at a glance where a setting lives.

Module 4: Opening it inside the shell#

cae/modules/settings/Settings.qmlpragma Singleton
import Quickshell
import QtQuick
import qs.modules.settings

// Opens the settings window inside the running shell (like Caelestia's Nexus).
// Only one window exists at a time; it is destroyed when closed.
Singleton {
    id: root

    property SettingsWindow window: null

    function open(): void {
        if (!root.window)
            root.window = windowComp.createObject(root);
    }

    Component {
        id: windowComp

        SettingsWindow {
            onClosed: {
                root.window = null;
                destroy();
            }
        }
    }
}

Module 5: Opening it as its own program#

cae/settings.qml//@ pragma UseQApplication
//@ pragma Env QS_NO_RELOAD_POPUP=1
//@ pragma Env QT_QUICK_CONTROLS_STYLE=Basic

import Quickshell
import QtQuick
import qs.modules.settings

// The settings app as its own program (like end-4's settings.qml):
//   qs -p ~/.config/quickshell/cae/settings.qml
// It edits ~/.config/cae/shell.json; the running shell notices the file change and updates.
ShellRoot {
    SettingsWindow {
        onClosed: Qt.quit()
    }
}

qs -p <file> runs a single QML file as a shell. The file's folder becomes the config root, so import qs.modules.settings finds the same modules, and the app uses its own copy of Config, Colours and Tokens, reading the same files as the shell. When the window closes, Qt.quit() ends the program.

Two things to be careful about in a second process:

  • Don't touch singletons that own system services. If the settings app used Notifs, it would start a second notification server; if it created GlobalShortcuts, they would collide with the shell's. The pages here only use Config, Colours, Tokens, Wallpapers and Profiles.
  • Actions that belong to the shell go through IPC. "Reload the shell" and the keybind "play" buttons run qs -c cae ipc call …, so they work the same from both modes.
In the original

end-4 starts its settings with qs -p ~/.config/quickshell/ii/settings.qml, from the right sidebar's settings button and the Super+I keybind. It sets Config.readWriteDelay = 0 on startup so each change is written immediately.
