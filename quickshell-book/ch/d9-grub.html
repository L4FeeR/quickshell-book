d9Desktop Ricing 9: GRUB Ricing

The boot menu is the first thing your machine shows, and on most installs it's a grey text list. GRUB can draw a full graphical menu with a background, icons for each system, a rounded highlight bar and a countdown bar. This chapter builds a complete theme, generates all its pictures and fonts with a script, and, most usefully, previews it in a virtual machine so you never have to reboot to see a change.

This is what the theme looks like booted in QEMU by preview.sh (redrawn here to keep the page light).

How GRUB themes work#

A GRUB theme is a folder:

tokyo/
├── theme.txt              the layout: what goes where, fonts, colours
├── background.png         the picture behind everything
├── logo.png               any extra picture you place
├── menu_*.png             nine pieces of the menu's panel
├── select_*.png           nine pieces of the highlight bar
├── progress_bar_*.png     nine pieces of the countdown's track …
├── progress_highlight_*.png   … and its fill
├── icons/arch.png …       one icon per menu entry "class"
└── *.pf2                  fonts, converted to GRUB's own format

GRUB is tiny and runs before your system, so it has strict rules. Knowing them saves hours:

Rule Why it matters
PNGs must be plain 8-bit RGB or RGBA. Palette or 1-bit PNGs (what image tools write for small single-colour pictures) are silently ignored: the piece just doesn't appear.
Fonts must be .pf2 files, made with grub-mkfont. A font is referred to as "Family Style Size", which must match the name inside the file.
Boxes are drawn from nine pieces (*_nw, _n, _ne, _w, _c, _e, _sw, _s, _se). Corners stay as they are, edges and the centre stretch. That's how a rounded box scales to any size.
The highlight is drawn around the entry, its corner pieces outside the entry's box. Leave enough spacing between entries, or the bar overlaps the next one.
Icons come from the entry's class: menuentry "Arch Linux" --class arch uses icons/arch.png. grub-mkconfig gives Arch entries the classes arch, gnu-linux, os; os-prober gives Windows windows.

The layout: theme.txt#

desktop/grub/tokyo/theme.txt# Tokyo Night GRUB theme
# Pictures and fonts come from make-assets.sh (run it once before installing).
# Positions are in pixels, percentages, or both ("50%-200"): the theme scales
# with the screen. Colours are #rrggbb.

# ── The whole screen ────────────────────────────────────────────────────────
title-text: ""                     # GRUB's own title off: we draw our own
desktop-image: "background.png"
desktop-color: "#16161e"           # behind the image, and if it fails to load
terminal-font: "Tokyo Regular 16"  # the command line (press c)
terminal-box: "menu_*.png"
message-font: "Tokyo Regular 16"
message-color: "#c0caf5"

# ── Logo and title above the menu ──────────────────────────────────────────
+ image {
    left = 50%-36
    top = 20%-36
    file = "logo.png"
}
+ label {
    left = 0
    top = 20%+48
    width = 100%
    align = "center"
    text = "Choose a system"
    font = "Tokyo Bold 22"
    color = "#c0caf5"
}

# ── The menu ───────────────────────────────────────────────────────────────
+ boot_menu {
    left = 50%-360
    top = 32%
    width = 720
    height = 36%

    menu_pixmap_style = "menu_*.png"         # the panel behind the entries
    item_font = "Tokyo Regular 18"
    item_color = "#a9b1d6"
    selected_item_font = "Tokyo Bold 18"
    selected_item_color = "#1a1b26"
    selected_item_pixmap_style = "select_*.png"   # the highlight bar

    icon_width = 32
    icon_height = 32
    item_icon_space = 16                     # gap between icon and text
    item_height = 40
    item_padding = 8                         # inside each entry
    item_spacing = 30                        # between entries: the highlight bar is drawn around the entry and grows into this gap
    scrollbar = false
}

# ── The countdown, as a bar that empties ───────────────────────────────────
+ progress_bar {
    id = "__timeout__"                       # this id makes it the timeout
    left = 50%-360
    top = 76%
    width = 720
    height = 26
    bar_style = "progress_bar_*.png"
    highlight_style = "progress_highlight_*.png"
    font = "Tokyo Regular 14"
    text_color = "#c0caf5"
    text = "@TIMEOUT_NOTIFICATION_MIDDLE@"   # "The highlighted entry will boot in 5s"
}

# ── Key help at the bottom ─────────────────────────────────────────────────
+ label {
    left = 0
    top = 100%-44
    width = 100%
    align = "center"
    text = "@KEYMAP_MIDDLE@"                 # "↑ ↓ to select, Enter to boot, e to edit…"
    font = "Tokyo Regular 14"
    color = "#545c7e"
}

Global settings (lines with a colon) apply to the whole screen: title-text (empty, because we draw our own title), desktop-image and desktop-color, and terminal-font/terminal-box for the command line you get by pressing c.

Components start with + and are placed with left, top, width, height. Values can be pixels (720), percentages of the screen (32%) or both (50%-360, which centres a 720-pixel box). That's how one theme works on any resolution.

Component Used here for Key properties
+ image the logo file
+ label the title, the key help text, font, color, align; the text @KEYMAP_MIDDLE@ becomes GRUB's key help
+ boot_menu the list of systems item_font, item_color, selected_item_*, menu_pixmap_style, selected_item_pixmap_style, icon size, heights and spacing
+ progress_bar the countdown id = "__timeout__" makes it count down the timeout; bar_style and highlight_style are its two nine-piece pictures; @TIMEOUT_NOTIFICATION_MIDDLE@ becomes "17s remaining"

Other components exist: + circular_progress (a countdown ring made of tick pictures), + hbox/+ vbox (rows and columns of components) and + canvas.

The numbers here (an entry height of 40, spacing of 30) came from previewing: the first version with taller entries and less spacing made the highlight bar touch the next entry.

Generating the pictures and fonts#

Drawing 36 tiny pictures by hand would be tedious, so a script makes them all from the palette:

desktop/grub/make-assets.sh#!/usr/bin/env bash
# Builds every picture and font the theme needs, into the theme folder.
# Needs ImageMagick (magick) and grub-mkfont (from the grub package).
# Usage: ./make-assets.sh [theme-folder] [font.ttf]
set -euo pipefail

dir="${1:-$(dirname "$0")/tokyo}"
font="${2:-/usr/share/fonts/TTF/JetBrainsMonoNerdFont-Regular.ttf}"
bold="${font/Regular/Bold}"; [ -f "$bold" ] || bold="$font"

bg="#16161e"; surface="#1a1b26"; raised="#24283b"; line="#292e42"
accent="#7aa2f7"; magenta="#bb9af7"; cyan="#7dcfff"

mkdir -p "$dir/icons"
cd "$dir"

# GRUB reads only plain RGB/RGBA PNGs. ImageMagick picks the smallest format by
# itself (palette, 1-bit…), which GRUB silently ignores, so every file is
# written with the PNG32: prefix (8-bit RGBA) or PNG24: (8-bit RGB).

# ── Background: a soft radial glow with a few wave lines ───────────────────
magick -size 1920x1080 radial-gradient:"$raised"-"$bg" \
    -fill none -strokewidth 2 -stroke "$line" \
    -draw "path 'M 0,780 C 480,700 960,880 1920,760'" \
    -draw "path 'M 0,830 C 520,740 1000,940 1920,810'" \
    -draw "path 'M 0,880 C 560,790 1040,990 1920,860'" \
    -depth 8 PNG24:background.png

# ── Nine-slice pictures ────────────────────────────────────────────────────
# GRUB draws boxes from 9 pieces: 4 corners (nw ne sw se), 4 edges (n e s w)
# that stretch, and a centre (c) that fills. slice NAME COLOUR RADIUS draws a
# rounded square and cuts it into NAME_nw.png … NAME_c.png.
slice() {
    local name=$1 colour=$2 r=$3 s=$(( $3 * 2 + 2 ))
    magick -size ${s}x${s} xc:none -fill "$colour" -draw "roundrectangle 0,0 $((s-1)),$((s-1)) $r,$r" "tmp_$name.png"
    local m=$(( s - 2 * r ))
    magick "tmp_$name.png" -crop ${r}x${r}+0+0         +repage -depth 8 "PNG32:${name}_nw.png"
    magick "tmp_$name.png" -crop ${m}x${r}+${r}+0      +repage -depth 8 "PNG32:${name}_n.png"
    magick "tmp_$name.png" -crop ${r}x${r}+$((r+m))+0  +repage -depth 8 "PNG32:${name}_ne.png"
    magick "tmp_$name.png" -crop ${r}x${m}+0+${r}      +repage -depth 8 "PNG32:${name}_w.png"
    magick "tmp_$name.png" -crop ${m}x${m}+${r}+${r}   +repage -depth 8 "PNG32:${name}_c.png"
    magick "tmp_$name.png" -crop ${r}x${m}+$((r+m))+${r} +repage -depth 8 "PNG32:${name}_e.png"
    magick "tmp_$name.png" -crop ${r}x${r}+0+$((r+m))  +repage -depth 8 "PNG32:${name}_sw.png"
    magick "tmp_$name.png" -crop ${m}x${r}+${r}+$((r+m)) +repage -depth 8 "PNG32:${name}_s.png"
    magick "tmp_$name.png" -crop ${r}x${r}+$((r+m))+$((r+m)) +repage -depth 8 "PNG32:${name}_se.png"
    rm "tmp_$name.png"
}
slice menu   "${surface}e6" 18      # the menu panel, slightly see-through
slice select "$accent" 8            # the highlight bar (its corners are drawn outside the entry)
slice progress_bar "$raised" 12     # the countdown's track
slice progress_highlight "$magenta" 12   # the countdown's fill

# ── Icons: one per menu entry class (--class arch, --class windows…) ───────
icon() {   # icon NAME COLOUR GLYPH
    magick -size 64x64 xc:none -fill "$2" -draw "roundrectangle 0,0 63,63 16,16" \
        -font "$font" -pointsize 38 -fill "$surface" -gravity center -annotate +0+2 "$3" \
        -depth 8 "PNG32:icons/$1.png"
}
icon arch    "$accent"  $''
icon cachyos "$cyan"    $''
icon linux   "$cyan"    $''
icon windows "$magenta" $''
icon efi     "$line"    $''
cp icons/efi.png icons/recovery.png

# ── The logo above the menu ────────────────────────────────────────────────
magick -size 72x72 xc:none -fill "$accent" -draw "circle 36,36 36,0" \
    -font "$font" -pointsize 40 -fill "$surface" -gravity center -annotate +0+2 $'' logo.png

# ── Fonts: GRUB only reads its own PF2 format ──────────────────────────────
# -n names the family, so theme.txt can say "Tokyo Regular 18".
for size in 14 16 18; do grub-mkfont -n Tokyo -s $size -o "tokyo-regular-$size.pf2" "$font"; done
grub-mkfont -n Tokyo -s 18 -b -o tokyo-bold-18.pf2 "$bold"
grub-mkfont -n Tokyo -s 22 -b -o tokyo-bold-22.pf2 "$bold"

echo "assets written to $dir"
  • Background: ImageMagick draws a radial gradient from the surface colour to the darkest colour, then three soft wave lines. PNG24: forces plain 8-bit RGB.
  • slice: draws one rounded square the size of two corners plus a two-pixel middle, then cuts it into the nine pieces GRUB expects. The PNG32: prefix on every piece is essential: without it, ImageMagick saves single-colour pieces as palette images, which GRUB ignores. (This was the bug in the first preview: the panel and highlight were simply missing.)
  • Four boxes: the menu panel (slightly see-through, e6 = 90% alpha), the highlight bar (smaller corners, because they're drawn outside the entry), and the countdown's track and fill.
  • Icons: a rounded square in a palette colour with a Nerd Font glyph (Arch, CachyOS, Tux, Windows, a gear for firmware settings). Add more for your systems: icon fedora "#7aa2f7" $''.
  • Fonts: grub-mkfont -n Tokyo -s 18 converts a TTF into a 18-pixel PF2 named "Tokyo Regular 18"; -b makes the bold one ("Tokyo Bold 18"). Every size used in theme.txt needs its own file.
cd examples/desktop/grub
./make-assets.sh          # writes everything into tokyo/

Previewing without rebooting#

desktop/grub/preview.sh#!/usr/bin/env bash
# Preview a GRUB theme without touching your boot setup: build a tiny bootable
# image with the theme and some fake menu entries, boot it in QEMU with no
# window, and save a screenshot of the menu.
# Needs: grub (grub-mkrescue), xorriso, mtools, qemu-system-x86_64, python3,
# and ImageMagick for the PNG.
# Usage: ./preview.sh [theme-folder] [screenshot.png] [WIDTHxHEIGHT]
set -euo pipefail

theme="$(realpath "${1:-$(dirname "$0")/tokyo}")"
out="$(realpath -m "${2:-grub-preview.png}")"
mode="${3:-1920x1080}"
work="$(mktemp -d)"
trap 'rm -rf "$work"' EXIT

name="$(basename "$theme")"
mkdir -p "$work/iso/boot/grub/themes"
cp -r "$theme" "$work/iso/boot/grub/themes/$name"

# The menu GRUB will show: fake entries with the classes real ones have,
# so the icons appear. Nothing here boots anything.
{
    echo "set gfxmode=$mode,auto"
    echo "insmod all_video"
    echo "insmod gfxterm"
    echo "insmod png"
    # load every font of the theme (grub-mkconfig does this for you on a real system)
    for f in "$theme"/*.pf2; do echo "loadfont /boot/grub/themes/$name/$(basename "$f")"; done
    echo "terminal_output gfxterm"
    echo "set theme=/boot/grub/themes/$name/theme.txt"
    echo "set timeout=30"
    echo 'menuentry "Arch Linux" --class arch { true }'
    echo 'menuentry "Arch Linux (fallback initramfs)" --class arch { true }'
    echo 'menuentry "Windows Boot Manager" --class windows { true }'
    echo 'menuentry "UEFI Firmware Settings" --class efi { true }'
} > "$work/iso/boot/grub/grub.cfg"

grub-mkrescue -o "$work/test.iso" "$work/iso" >/dev/null 2>&1

# Boot it headless. QEMU's monitor listens on a local TCP port; sending it
# "screendump FILE" saves the screen, "quit" stops the machine.
port="${PREVIEW_PORT:-45541}"
qemu-system-x86_64 -m 256 -cdrom "$work/test.iso" -vga std -display none \
    -monitor "tcp:127.0.0.1:$port,server,nowait" &
qemu=$!
sleep "${PREVIEW_WAIT:-15}"          # GRUB takes a few seconds to load its fonts and pictures
python3 - "$port" "$work/shot.ppm" <<'PY'
import socket, sys, time
s = socket.create_connection(("127.0.0.1", int(sys.argv[1]))); time.sleep(0.3)
s.sendall(f"screendump {sys.argv[2]}\n".encode()); time.sleep(1)
s.sendall(b"quit\n"); time.sleep(0.5)
PY
wait "$qemu" 2>/dev/null || true
magick "$work/shot.ppm" "$out"
echo "screenshot: $out"

This builds a tiny bootable image (with grub-mkrescue) containing your theme and four fake menu entries with the right classes, boots it in QEMU without a window, waits for GRUB to draw, and asks QEMU's monitor for a screenshot. Nothing on your machine is touched; the image is deleted afterwards.

sudo pacman -S --needed qemu-desktop xorriso mtools
./preview.sh tokyo grub-preview.png 1920x1080

Change theme.txt or the colours in make-assets.sh, run both scripts again, and look at the new screenshot: a theme loop of a few seconds instead of a reboot. If the picture is blank, GRUB hadn't finished drawing: raise the wait with PREVIEW_WAIT=20 ./preview.sh.

Installing#

desktop/grub/install.sh#!/usr/bin/env bash
# Install the theme on this machine (needs sudo). Backs up /etc/default/grub,
# sets the theme and a screen mode, and regenerates GRUB's config.
# Undo: restore the backup, then run the grub-mkconfig line at the end again.
set -euo pipefail

theme="$(realpath "${1:-$(dirname "$0")/tokyo}")"
name="$(basename "$theme")"
mode="${2:-auto}"                       # e.g. 1920x1080, or auto

[ -f "$theme/background.png" ] || { echo "run ./make-assets.sh first"; exit 1; }
read -rp "Install GRUB theme '$name' (mode $mode)? [y/N] " ok
[ "$ok" = y ] || exit 0

sudo mkdir -p /boot/grub/themes
sudo cp -r "$theme" "/boot/grub/themes/$name"
sudo cp /etc/default/grub "/etc/default/grub.bak-$(date +%Y%m%d-%H%M%S)"

# replace (or add) the two settings
set_opt() {
    if grep -q "^#\?$1=" /etc/default/grub; then
        sudo sed -i "s|^#\?$1=.*|$1=\"$2\"|" /etc/default/grub
    else
        echo "$1=\"$2\"" | sudo tee -a /etc/default/grub >/dev/null
    fi
}
set_opt GRUB_THEME "/boot/grub/themes/$name/theme.txt"
set_opt GRUB_GFXMODE "$mode"
# the theme needs the graphical terminal, not the text console
sudo sed -i 's|^GRUB_TERMINAL_OUTPUT=.*|#&|' /etc/default/grub

sudo grub-mkconfig -o /boot/grub/grub.cfg
echo "done: reboot to see it"

It asks before doing anything, copies the theme to /boot/grub/themes/, backs up /etc/default/grub, sets GRUB_THEME and GRUB_GFXMODE (the screen mode: auto, or your monitor's resolution if the picture looks stretched), comments out GRUB_TERMINAL_OUTPUT (a text console setting there disables themes), and regenerates grub.cfg. grub-mkconfig also loads every .pf2 in the theme folder for you.

./install.sh tokyo 1920x1080
Before you install

Keep a live USB at hand. If GRUB shows a plain menu after installing, the theme failed to load (usually a wrong path or font name): it still boots normally. To undo, restore the backup (sudo cp /etc/default/grub.bak-… /etc/default/grub) and run sudo grub-mkconfig -o /boot/grub/grub.cfg. On systems using systemd-boot instead of GRUB (some CachyOS and EndeavourOS installs), there are no themes: bootctl status tells you which you have.

Ready-made themes#

Popular themes follow the same layout, so you can read and change them: catppuccin/grub, vinceliuice/grub2-themes (Tela, Vimix, Stylish), Jacksaur/CRT-Amber-GRUB-Theme. Most ship an install script; preview.sh works with any of them (./preview.sh /path/to/theme).
