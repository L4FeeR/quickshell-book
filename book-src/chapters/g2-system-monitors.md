# Gallery: System Monitors and Live Stats

Live numbers about your machine: network speed, CPU, memory, temperature, GPU, disk. Most read Linux's `/proc` and `/sys` files directly with [[FileView]], which is far cheaper than running commands.

> [!TIP] Put the reading logic in a service
> Each example is self-contained for easy testing. In your real shell, move the `FileView` + `Timer` parts into one `services/SystemStats.qml` singleton ([[ch:33-singletons]]) so the bar, a dashboard and desktop widgets share one reader.

## Live Network Speed

**What it is.** Live download and upload speed, updated every second, with automatic units (B/s, KB/s, MB/s). Hover to see the interface name and totals since boot.

**Kind:** bar module · **Needs:** nothing extra (reads `/proc/net/dev`)

@include galleryshell/bar/NetSpeed.qml

::: walk
The idea: the kernel keeps a running total of bytes sent and received per network interface. Read it once a second; the difference between two readings is the speed.
@ 6-13 | State
`down`/`up` are the current speeds in bytes per second, `totalDown`/`totalUp` the totals since boot, `iface` the active interface names. `last` remembers the previous sample (`rx` bytes, `tx` bytes, time `t`) so we can compute differences.
@ 15-20 | Human-readable speed
Divide by 1024 until the number is small enough, moving to the next unit each time. Numbers of 100 or more are rounded (`123 KB/s`); smaller ones keep one decimal (`4.2 MB/s`). Plain bytes are never shown with decimals.
@ 21-25 | Human-readable totals
Same loop for totals, always with one decimal.
@ 27 | The source file
[[FileView]] reads `/proc/net/dev`. This "file" is generated by the kernel each time it's read, so we must `reload()` it to get fresh numbers.
@ 29-32 | Every second
A repeating timer re-reads the file. `triggeredOnStart` takes the first sample immediately.
@ 34-43 | Parsing the lines
The first two lines are headers (`slice(2)`). Each other line is `name: numbers…`. The regex splits the name from the numbers. Virtual interfaces are skipped: `lo` (loopback, your own machine), Docker, VM bridges; otherwise local traffic would inflate the numbers. Field 0 is received bytes and field 8 sent bytes. Totals of all real interfaces are summed, so it works on Wi-Fi and Ethernet at the same time.
@ 44-50 | Speed = difference ÷ time
With a previous sample, `(rx - last.rx) / dt` is bytes per second. We divide by the *measured* elapsed time instead of assuming exactly 1 s, because timers can be a little late. `Math.max(0, …)` protects against counters resetting (an interface reconnecting). Then the current sample becomes the new `last`.
@ 61-70 | Download display
A blue arrow and the formatted speed. `Layout.preferredWidth: 64` gives the number a fixed slot, so the bar doesn't shift every second as digit counts change.
@ 77-81 | Details on hover
Interface names and session totals, only while hovered.
:::

**Customize**
- Show only one interface: filter `name === "wlan0"`.
- Bits instead of bytes: multiply by 8 and use `Kb/s, Mb/s`.
- Hide when idle: `visible: root.down + root.up > 1024`.
- Add a sparkline: see the CPU example below and keep a history array for `down`.

::: exercise practice | Hide when idle
Fade the widget to 40% opacity when both speeds are under 1 KB/s.
--- solution
```qml
opacity: root.down < 1024 && root.up < 1024 && !hover.hovered ? 0.4 : 1
Behavior on opacity { NumberAnimation { duration: 300 } }
```
:::

## CPU Usage with Sparkline

<div class="preview"><svg width="260" height="60" viewBox="0 0 260 60"><rect x="20" y="15" width="220" height="30" rx="15" fill="#313244"/><text x="38" y="35" fill="#cba6f7" font-size="12" font-weight="700">CPU</text><text x="70" y="35" fill="#cdd6f4" font-size="13" font-weight="700">37%</text><polyline fill="none" stroke="#cba6f7" stroke-width="2" stroke-linejoin="round" points="110,36 120,30 130,33 140,24 150,28 160,22 170,31 180,26 190,34 200,21 210,27 220,25"><animate attributeName="points" dur="4s" repeatCount="indefinite" values="110,36 120,30 130,33 140,24 150,28 160,22 170,31 180,26 190,34 200,21 210,27 220,25;110,30 120,33 130,24 140,28 150,22 160,31 170,26 180,34 190,21 200,27 210,25 220,32;110,36 120,30 130,33 140,24 150,28 160,22 170,31 180,26 190,34 200,21 210,27 220,25"/></polyline></svg></div>

**What it is.** CPU usage percentage plus a tiny live graph of the last 30 seconds.

**Kind:** bar module · **Needs:** nothing extra (reads `/proc/stat`)

@include galleryshell/bar/CpuSpark.qml

::: walk
@ 5-10 | State
`usage` is 0–1. `history` holds the last 30 values for the graph. `last` stores the previous counters.
@ 12-19 | Reading /proc/stat
The first line of `/proc/stat` lists how much time all CPUs have spent in each state since boot (user, nice, system, idle, iowait…). We drop the word `cpu`, convert the rest to numbers, and count **idle + iowait** as idle time.
@ 20-26 | Usage over the last second
The counters only grow, so we compare with the previous reading: of all the time that passed (`dTotal`), how much was idle? `1 - idleDelta / dTotal` is the busy fraction. The new value is added to `history` by creating a **new array** (`[...history, usage]`) and trimming it to 30 with `slice(-30)`. Using `push()` would not emit `historyChanged`.
@ 39-41 | Number display
Turns red above 85%. A fixed width keeps it steady.
@ 42-58 | Drawing the sparkline
- `ctx.reset()` clears the previous drawing.
- `step` is the horizontal distance between points; `x0` right-aligns the graph so new values appear on the right while it fills up.
- For each value, `y = height - v * height` (0% at the bottom, 100% at the top). The first point uses `moveTo`, the rest `lineTo`.
- After stroking the line, we continue down to the bottom corners and close the path, then fill it with a transparent version of the color (`#33` = 20% alpha), giving the soft area under the line.
@ 59 | When to repaint
A Canvas only redraws when asked. Every time `history` changes we call `requestPaint()`.
:::

**Customize**
- Per-core bars: read the `cpu0`, `cpu1`… lines and draw one thin bar each.
- Show the top process on hover: `ps -eo comm,%cpu --sort=-%cpu | sed -n 2p` with [[Process]].

::: exercise practice | Per-core
Show per-core usage as a row of tiny vertical bars (the lines `cpu0`, `cpu1`… in `/proc/stat`).
--- hint
Keep `last` as an array of `{ total, idle }`, one per core line (`lines.filter(l => /^cpu\d/.test(l))`).
:::

## Memory Bar

<div class="preview"><svg width="260" height="60" viewBox="0 0 260 60"><rect x="20" y="15" width="220" height="30" rx="15" fill="#313244"/><text x="38" y="35" fill="#94e2d5" font-size="12" font-weight="700">RAM</text><rect x="74" y="27" width="100" height="6" rx="3" fill="#45475a"/><rect x="74" y="27" width="58" height="6" rx="3" fill="#94e2d5"><animate attributeName="width" values="52;64;58;52" dur="5s" repeatCount="indefinite"/></rect><text x="182" y="35" fill="#cdd6f4" font-size="12">9.1/16G</text></svg></div>

**What it is.** Used RAM as a bar plus "used/total" in GB; hover shows swap.

**Kind:** bar module · **Needs:** nothing extra (reads `/proc/meminfo`)

@include galleryshell/bar/MemoryBar.qml

::: walk
@ 5-11 | State
Values in kilobytes, as `/proc/meminfo` reports them. `ratio` is used/total. `totalKb` starts at 1 so `ratio` never divides by zero before the first read.
@ 13-16 | Reading one field
Builds a regex like `^MemTotal:\s+(\d+)` with the `m` (multiline) flag, so `^` matches at the start of any line. Returns the number or 0.
@ 18-29 | Every 3 seconds
Memory changes slowly, so 3 s is plenty. **Used = MemTotal − MemAvailable**. `MemAvailable` includes file cache the kernel can free instantly, so this matches what `free` and other monitors call "used". Swap used is total minus free.
@ 41-48 | The bar
A 60×6 track and fill. The color warns at 75% (yellow) and 90% (red).
@ 49-54 | Text
Dividing kilobytes by 1048576 (1024 × 1024) gives gigabytes. On hover it shows swap usage instead, but only if you have swap.
:::

::: exercise practice | Top process tooltip
On hover, also show the most memory-hungry process name (`ps -eo comm --sort=-%mem | sed -n 2p`), refreshed only while hovered.
:::

## CPU Temperature

<div class="preview"><svg width="200" height="60" viewBox="0 0 200 60"><rect x="40" y="15" width="120" height="30" rx="15" fill="#313244"/><rect x="60" y="21" width="6" height="14" rx="3" fill="none" stroke="#fab387" stroke-width="2"/><circle cx="63" cy="37" r="4" fill="#fab387"/><rect x="61.5" y="27" width="3" height="9" fill="#fab387"><animate attributeName="y" values="29;23;29" dur="3s" repeatCount="indefinite"/><animate attributeName="height" values="7;13;7" dur="3s" repeatCount="indefinite"/></rect><text x="112" y="35" fill="#fab387" font-size="13" font-weight="700" text-anchor="middle">67°C</text></svg></div>

**What it is.** CPU package temperature, color-coded: normal, warm (≥70 °C), hot (≥85 °C, pulsing).

**Kind:** bar module · **Needs:** nothing extra (reads `/sys/class/hwmon`)

@include galleryshell/bar/CpuTemp.qml

::: walk
@ 9-14 | Finding the right sensor
Temperature sensors live in `/sys/class/hwmon/hwmon0`, `hwmon1`… and their numbering changes between boots. The shell loop reads each `name` file and picks the CPU driver: `coretemp` (Intel), `k10temp` or `zenpower` (AMD). If none matches, it falls back to the generic `thermal_zone0`. This runs once at startup.
@ 15-19 | Reading it
Once the path is known, a `FileView` reads that one tiny file every 2 seconds. The value is in millidegrees (`54000` = 54 °C), hence `/ 1000`. `running: root.sensorPath !== ""` waits until the path is found.
@ 21 | Color by heat
Green below 70 °C, orange from 70, red from 85.
@ 34-36 | Blink when hot
The label blinks while ≥ 85 °C. `onStopped: label.opacity = 1` restores full opacity when it cools down, otherwise the text could stay half-transparent.
:::

**Customize**
- GPU temperature (AMD): the hwmon whose name is `amdgpu`. NVMe: name `nvme`.
- Show the fan speed: `fan1_input` in the same hwmon folder.

::: exercise practice | Fahrenheit option
Add `property bool fahrenheit` that shows °F (`c * 9 / 5 + 32`).
:::

## GPU Usage

<div class="preview"><svg width="220" height="60" viewBox="0 0 220 60"><rect x="30" y="15" width="160" height="30" rx="15" fill="#313244"/><text x="50" y="35" fill="#a6e3a1" font-size="12" font-weight="700">GPU</text><text x="90" y="35" fill="#cdd6f4" font-size="13" font-weight="700">54%</text><text x="125" y="35" fill="#a6adc8" font-size="12">3.1G</text></svg></div>

**What it is.** GPU utilization and VRAM use, for NVIDIA (`nvidia-smi`) or AMD (sysfs).

**Kind:** bar module · **Needs:** NVIDIA drivers, or an AMD GPU

@include galleryshell/bar/GpuUsage.qml

::: walk
@ 10-14 | Which GPU?
If `nvidia-smi` exists we're on NVIDIA; if any card has `gpu_busy_percent` in sysfs, it's AMD. The result decides which reader runs. Intel GPUs report neither, so the widget hides.
@ 15-22 | NVIDIA: one long-running process
`nvidia-smi -l 2` keeps running and prints one CSV line every 2 seconds (`45, 2048`). [[SplitParser]] calls `onRead` per line; we split on the comma, convert, and store usage (%) and VRAM (MiB → GiB). No timer needed, and no new process every tick.
@ 23-29 | AMD: sysfs files
AMD drivers expose usage and VRAM bytes as plain files. Two FileViews are re-read every 2 seconds. The path is `""` on non-AMD machines, so nothing is read there. Your card may be `card0` instead of `card1`.
@ 31-42 | Display
Hidden if no supported GPU was found.
:::

::: exercise practice | Find the card automatically
Detect the AMD card path in the same detection script instead of hard-coding `card1`.
--- hint
Print the matching `gpu_busy_percent` path itself (`ls /sys/class/drm/card*/device/gpu_busy_percent | head -1`) and derive the folder from it.
:::

## Disk Usage Ring

<div class="preview"><svg width="140" height="80" viewBox="0 0 140 80"><circle cx="70" cy="40" r="26" fill="none" stroke="#45475a" stroke-width="6"/><circle cx="70" cy="40" r="26" fill="none" stroke="#f9e2af" stroke-width="6" stroke-linecap="round" stroke-dasharray="113 163" transform="rotate(-90 70 40)"><animate attributeName="stroke-dasharray" values="0 163;113 163" dur="1.5s" fill="freeze"/></circle><text x="70" y="44" fill="#cdd6f4" font-size="13" font-weight="700" text-anchor="middle">69%</text></svg></div>

**What it is.** A circular gauge showing how full a disk is, with free space on hover.

**Kind:** bar module or dashboard · **Needs:** `df` (coreutils)

@include galleryshell/bar/DiskRing.qml

::: walk
@ 5-10 | Properties
`mount` lets you place several rings for different disks (`"/"`, `"/home"`). `used` is 0–1.
@ 12-22 | Asking df
`df -B1 --output=pcent,avail /` prints a header line and then e.g. `  45%  512000000000`. We take line 2, split on spaces, and parse the percentage and free bytes (÷ 1073741824 = GiB).
@ 23 | Once a minute
Disk usage changes slowly.
@ 26-32 | Background ring
A full circle (`sweepAngle: 360`) in a dark color: the track. `CurveRenderer` draws smooth, anti-aliased curves.
@ 33-38 | Usage arc
Starts at the top (`startAngle: -90`) and sweeps clockwise in proportion to usage. `RoundCap` gives round ends. Red above 90%.
@ 40-43 | Number and hover text
The percentage sits in the middle; "512G free" appears to the right on hover.
:::

::: exercise practice | Two disks
Put two rings side by side for `/` and `/home`, each with its own color.
:::

## Uptime

<div class="preview"><svg width="200" height="60" viewBox="0 0 200 60"><rect x="40" y="15" width="120" height="30" rx="15" fill="#313244"/><circle cx="60" cy="30" r="7" fill="none" stroke="#89b4fa" stroke-width="2"/><path d="M60 26v4l3 2" stroke="#89b4fa" stroke-width="2" fill="none"/><text x="112" y="35" fill="#cdd6f4" font-size="13" text-anchor="middle">2d 4h 17m</text></svg></div>

**What it is.** How long the system has been running.

**Kind:** bar module · **Needs:** nothing extra (reads `/proc/uptime`)

@include galleryshell/bar/Uptime.qml

::: walk
@ 6-10 | Formatting
`/proc/uptime` gives seconds. The block splits them into days, hours and minutes, and hides parts that are zero: `3h 12m`, `2d 0h 5m`. `d || h` keeps the hours when there are days.
@ 11-13 | Reading
The first number in `/proc/uptime` is the uptime in seconds (the second is idle time). A minute timer is enough since we don't show seconds.
:::

::: exercise practice | Since date
Show the boot time on hover ("since Mon 09:12") by subtracting `secs` from now.

## Ping / Latency Indicator

<div class="preview"><svg width="200" height="60" viewBox="0 0 200 60"><rect x="40" y="15" width="120" height="30" rx="15" fill="#313244"/><circle cx="60" cy="30" r="5" fill="#a6e3a1"><animate attributeName="r" values="4;6;4" dur="1.5s" repeatCount="indefinite"/></circle><text x="112" y="35" fill="#cdd6f4" font-size="13" text-anchor="middle">23 ms</text></svg></div>

**What it is.** Round-trip time to a host (default 1.1.1.1) every 5 seconds: green fast, yellow slow, red offline.

**Kind:** bar module · **Needs:** `ping` (iputils)

@include galleryshell/bar/Ping.qml

::: walk
@ 7-8 | State
`host` defaults to Cloudflare DNS (fast and always up). `ms` is −1 when unreachable.
@ 10-21 | One ping
`ping -c 1 -W 2`: one packet, wait at most 2 seconds. `LC_ALL: "C"` forces English output so the regex `time=([\d.]+)` matches on any system language. A non-zero exit code means no reply, so we set −1.
@ 22 | Every 5 seconds
Frequent enough to notice problems, cheap enough to not matter.
@ 24 | Quality colors
Red offline, green < 60 ms, yellow < 150 ms, orange above.
@ 29-30 | Status dot
The dot crossfades between colors instead of jumping.
:::

::: exercise practice | Average
Show the average of the last 10 pings instead of only the latest.
:::

## Battery Power Draw

<div class="preview"><svg width="240" height="60" viewBox="0 0 240 60"><rect x="30" y="15" width="180" height="30" rx="15" fill="#313244"/><path d="M52 22l-6 9h5l-2 8 7-10h-5z" fill="#f9e2af"/><text x="70" y="35" fill="#cdd6f4" font-size="12">−9.4 W · 3h 12m left</text></svg></div>

**What it is.** How fast the battery is draining (or charging) in watts, plus time remaining, useful for spotting power-hungry apps.

**Kind:** bar module · **Needs:** UPower

@include galleryshell/bar/PowerDraw.qml

::: walk
@ 6-10 | Reading
`changeRate` is the power flowing in or out of the battery in watts. `secs` picks time-to-full or time-to-empty depending on the state.
@ 13-21 | Text
`Math.abs` hides driver differences in the sign, and we add our own `+`/`−` based on the charging state. Time is appended only when UPower knows it (> 0). Drawing more than 20 W on battery turns the text orange: something is working hard.
:::
