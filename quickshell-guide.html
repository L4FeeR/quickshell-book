Part 0 · Orientation

0.1 What Quickshell actually is

Quickshell is a toolkit for building desktop shell components (bars, panels, widgets, lock screens, launchers, notification popups) on Wayland, and partly on X11. You write the UI in QML, the declarative language of Qt Quick. Quickshell gives QML extra types: Wayland layer-shell windows, compositor integrations (Hyprland, Sway/i3), system services (PipeWire audio, MPRIS media, UPower battery, the system tray, a notification server, Bluetooth, PAM auth), and process and file I/O.

The idea in one sentence: a Quickshell config is a small Qt app, written in a declarative language, that the shell hot-reloads every time you hit save.

Why people switch to it

vs Waybar

Waybar is a configurable bar: JSON plus CSS, fixed modules. Quickshell is a toolkit, so the bar is just one thing you build. You can also build popups, overviews and lock screens, all sharing state.

vs EWW

EWW uses Yuck plus GTK CSS and polls scripts. Quickshell has native service bindings (no polling for volume or battery), GPU-accelerated animations and a real language.

vs AGS / Astal

Similar power, but JS/TS plus GTK. Quickshell uses QML: declarative bindings, very fast hot reload, Qt's animation system, plus built-in Wayland/Hyprland types.

Performance

Native C++ services, a scene graph on the GPU, and lazy loading. A full end-4-style shell idles at a fraction of a percent of CPU when written well (Part X).

Part II · The QML language, from a single line

2.1 Objects, types and nesting

A QML file describes a tree of objects. Each object has a type (capitalized: Rectangle), a body in { }, and inside the body you set properties or declare child objects.

  • Imports come first. import QtQuick brings in the visual basics, import Quickshell brings in Quickshell. No version numbers are needed in Qt 6.
  • A file has exactly one root object.
  • Children are drawn on top of their parent, and later siblings on top of earlier ones (or use z).
  • Semicolons are optional at line ends and required when you put several properties on one line: width: 10; height: 10.
  • Comments: // line and /* block */.

2.2 Properties & value types

Built-in types have properties already (width, color…). You can declare your own with property TYPE name: value.

TypeExampleNotes
int / real42 / 4.2Division always gives a real: 5/2 === 2.5. Use Math.floor.
string"a", 'a', `v=${x}`Template strings work.
color"#80000000"The alpha comes first in 8-digit hex (Qt style, not CSS!). Qt.alpha(c, 0.5) needs Qt 6.8+, otherwise use Qt.rgba(c.r, c.g, c.b, 0.5).

Classic beginner bug

property var obj: { a: 1 } is parsed as a code block, not an object. Always wrap object literals in parentheses: ({ a: 1 }).

2.3 ids: naming objects so you can reference them

By convention the root object is called root. Inside a file an id can be used from anywhere. Outside the file it's invisible, so you expose things with properties instead.

Special names: parent is the visual parent item, and this is the current object inside a function or handler.

2.4 Bindings: the heart of QML

When a property's value is an expression, QML records which other properties it reads and re-evaluates it automatically whenever any of them change. That is a binding. It's why a QML bar needs almost no "update" code.

Bindings vs assignments

A binding lives until you assign to the property imperatively (with = in JavaScript). The assignment replaces the binding with a fixed value.

Rule of thumb

Describe what things are with bindings (declarative). Use JS assignments only for events (a click, a timer, a process finishing). If something "stops updating", you've probably broken a binding with an assignment.

2.9 Scope rules & how name lookup works

When an expression uses a bare name like height, QML looks in this order:

  1. JS locals and function parameters
  2. Properties of the current object
  3. ids in the same file
  4. Properties of the file's root object
  5. Context from outside the file (e.g. modelData from a delegate, though declaring it as a required property is cleaner)
  6. Singletons and imported type names
Be explicit

Write root.height rather than height when you mean the root. Unqualified lookups to outer objects are a common source of "why does this resolve to the wrong thing", and they're slower.

3.2 Sizing: width vs implicitWidth

This single concept causes most layout confusion. implicitWidth/Height is the size an item would like to be, based on its content (Text sets it from the text). width/height is the size it actually is. By default width follows implicitWidth.

  • Components you write should set implicitWidth/implicitHeight from their content, so users can lay them out.
  • Users of a component set width/height (or anchors, or Layout properties) to override.
  • Quickshell windows use implicitWidth/implicitHeight for their size (older code used width/height, which are deprecated on windows).

3.3 Anchors: gluing edges together

Anchor lines: left right top bottom horizontalCenter verticalCenter baseline. Shortcuts: fill and centerIn. Margins: margins, leftMargin… You can only anchor to your parent or siblings.

Don't fight yourself

Never set both anchors.left/right and width, or anchors and x. Anchors win and you'll get warnings.

4.3 Variants: one window per monitor

Variants creates one copy of its child for every entry in model, and creates or destroys copies when the model changes. With Quickshell.screens that means a bar per monitor that follows hotplugging.

ShellScreen has name (e.g. "DP-1"), model, width, height, x, y, devicePixelRatio, physicalPixelDensity, orientation.

Only some monitors

model: Quickshell.screens.filter(s => s.name !== "HDMI-A-1"). Or pick by config: filter(s => Config.bar.screens.includes(s.name)).

Inside the window, QsWindow.window (an attached property) gives any nested item a reference to its containing window. That's handy for popups in deeply nested widgets.

4.4 FloatingWindow: a normal app window

Use it for settings apps, debug panels, or anything that should be a regular tiled or floating window instead of a layer surface.

4.5 PopupWindow: menus and tooltips attached to a window

A PopupWindow is positioned relative to another window (your bar). It's perfect for dropdowns like a calendar under the clock or a tray menu.

Closing when clicking elsewhere

Use HyprlandFocusGrab (6.4) on Hyprland. Elsewhere, use a fullscreen transparent PanelWindow behind the popup that closes it on click.

4.6 LazyLoader: create windows only when needed

Every hidden window still costs memory. LazyLoader creates its child when active becomes true and destroys it when false. Set loading: true to pre-build it in the background so it pops instantly.

In the wild

end-4 wraps almost every panel (sidebars, overview, session screen, cheatsheet) in a LazyLoader or Loader driven by a GlobalStates singleton. Caelestia does the same per drawer.

4.7 Singletons: global state & services

A singleton is a type with exactly one instance, accessible by name from any file. It's the backbone of every big rice: Audio, Battery, Network, Config, Colors, GlobalStates.

Gotchas
  • Singletons are created lazily, on first use. A singleton nobody references never runs. If it must run at startup (e.g. a notification server), reference it from shell.qml: Component.onCompleted: Notifs.init(), or read a property.
  • Only use pragma Singleton on files in a folder you import. You don't need a qmldir file: Quickshell detects the pragma.

4.8 Region & mask: click-through windows

By default a window eats all clicks inside its rectangle. mask limits the clickable/visible input area to a Region. This is the trick behind Caelestia's architecture: one fullscreen transparent window per monitor holding bar, drawers and popups, with clicks only captured where something is actually visible.

Region properties: item (or x y width height), shape: RegionShape.Rect | Ellipse, intersection: Intersection.Combine | Subtract | Intersect | Xor, plus nested child regions. Because a mask follows the item's geometry automatically, animating the drawer animates the clickable area too.

Reserve space separately

A fullscreen window with ExclusionMode.Ignore doesn't push tiled windows aside. Add a second invisible PanelWindow per screen with exclusiveZone: barHeight and no content (Caelestia calls this the "exclusion" window).

4.9 ObjectModel, ScriptModel & data flow

Service lists such as Hyprland.workspaces, Mpris.players, SystemTray.items, Pipewire.nodes and DesktopEntries.applications are ObjectModels:

  • Pass them directly as model: to Repeater, ListView or Variants. The delegate gets modelData.
  • .values gives a JS array (bindings update when the list changes) for filter, sort, find.

5.5 IpcHandler: control your shell from keybinds and scripts

The cleanest way to let scripts, keybinds or other programs drive your shell. Declare a target and functions. Quickshell exposes them via qs ipc call.

Types are mandatory

IPC functions must have typed parameters and a return type (: void, : string, : int, : bool, : real, : color). Untyped functions aren't exposed. Handlers can also expose properties, readable with qs ipc prop get.

In the wild

Caelestia exposes targets like drawers, mpris, notifs, wallpaper, and its caelestia CLI wraps qs ipc call. JaKooLit-style setups bind keys to qs ipc call so Quickshell can coexist with Waybar.

6.8 WlSessionLock: real lock screens

WlSessionLock uses the ext-session-lock protocol: the compositor guarantees nothing else is shown or receives input while locked. Even if your shell crashes, the screen stays locked (it shows a red/blank screen, never your desktop).

Never unlock without authentication

Only set locked = false after PamContext reports success. Test lock screens using a nested session or a test config with a timeout fallback, so you can't lock yourself out while developing (Project 9.7).

7.1 Audio: Quickshell.Services.Pipewire

#1 audio mistake

Without PwObjectTracker, sink.audio.volume is 0 or undefined and setting it does nothing. Track every node whose audio you read or write.

Using it

Per-app volume mixer

Switch output device: Pipewire.preferredDefaultAudioSink = node. List devices: Pipewire.nodes.values.filter(n => n.isSink && !n.isStream). The golden rule

services know nothing about UI; modules know nothing about the system. Modules read service properties and call service functions. That makes services reusable (bar and sidebar both use Audio) and lets you swap implementations (e.g. nmcli → Networking module) without touching UI.

8.2 A design system: styled primitives

8.3 Material You colors from your wallpaper (matugen)

That "everything matches the wallpaper" look is a pipeline: wallpaper → matugen → colors.json → FileView in a Colors singleton → every widget binds to it. Because everything is a binding, the whole shell recolors live, and with Behavior on color it even crossfades.

In the wild

end-4's switchwall.sh runs matugen plus its own Python color generation and writes JSON that its Appearance singleton watches. Caelestia's caelestia scheme CLI writes a scheme file that its Colours singleton loads (it also supports static schemes like Catppuccin). Same pipeline, different generators.

Static themes

Want Catppuccin, Gruvbox or Rosé Pine instead? Ship themes/catppuccin.json files with the same keys and point the FileView path at Config.appearance.theme. Theme switching is then one property change.

8.4 Appearance tokens: rounding, spacing, fonts, motion

10.2 Performance checklist

  1. Lazy-load every panel that isn't always visible (LazyLoader/Loader).
  2. No polling where a service exists: Pipewire, UPower, Mpris and Hyprland are all event-driven.
  3. When you must poll, use long intervals and stop when hidden: running: panel.visible.
  4. SystemClock.Minutes instead of seconds when possible.
  5. Images: always set sourceSize (decoding a 4K wallpaper for a 260px thumbnail wastes ~30 MB each) and asynchronous: true.
  6. ScreencopyView.live only while visible.
  7. Avoid layer.enabled / MultiEffect on things that animate constantly: each is an offscreen render pass.
  8. Infinite animations keep the render loop at 60+ fps forever. Bind running to visibility.
  9. Use ScriptModel for filtered lists so delegates are reused.
  10. Prefer FileView over Process for reading files (no fork/exec).
  11. Avoid heavy JS in bindings that re-evaluate often. Precompute in a readonly property.

Measure: top -p $(pgrep -f "qs -c myshell"). A well-built full shell should sit near 0% CPU at idle.

10.4 Beyond QML: C++ plugins and other languages

When JS isn't enough (heavy audio DSP, image processing, a custom protocol), write a QML extension plugin in C++ with CMake, qt_add_qml_module and QML_ELEMENT, install it into a QML import path, and import MyPlugin. Caelestia does exactly this for its visualizer. Lighter alternatives:

  • A helper binary/script (Python, Rust, Go) that prints JSON lines → Process + SplitParser + JSON.parse.
  • A daemon with a Unix socket → Socket.
  • Anything with a D-Bus API → wrap it with busctl/gdbus monitor through Process.

10.5 Sharing your rice

  • Put your config in a git repo. Install it with ln -s ~/dotfiles/quickshell/myshell ~/.config/quickshell/myshell.
  • Keep user-specific values (wallpaper dir, terminal, API keys) in the JSON config, never hard-coded.
  • Document dependencies: Quickshell version, fonts (Material Symbols, your UI font), CLI tools (matugen, brightnessctl, cliphist, nmcli…).
  • Provide fallbacks: Colors defaults if colors.json doesn't exist; hide modules whose tool is missing (Process { command: ["which", "cliphist"] }).
  • Add a README with screenshots and your keybinds file.
